Preflight PREFLIGHT

Every push is cleared for takeoff.

pre·flight noun The checklist a pilot runs before takeoff. Every push runs this one before Citadel.

Preflight is a set of GitLab CI/CD components. Add them to the include: block in your .gitlab-ci.yml and your pipeline runs PROCTOR, PHP tests on each supported version, a Composer audit, an SBOM, Pint, PHPStan and ESLint, the same way the other stack apps do.

.gitlab-ci.yml

include:
  - component: $CI_SERVER_FQDN/enterprise-apps/preflight/php-test@87d9b6fc6b0ed302dd729986525282cd7b567ebd # 0.4.0

Already included in WELD and in every Sourdough app. Use Preflight on its own to give a GitLab project you already have the stack's CI checks.

WSU app stack · normal checklist

Before takeoff · every push

  1. PROCTORChecked

    Checks the app against the stack's standards and publishes the result as a GitLab Code Quality report.

    vendor/bin/proctor check --format=codequality

  2. PHP tests8.3 · 8.4 · 8.5 pass

    One job per supported PHP version, through parallel:matrix. End-of-life PHP is not on the list.

    vendor/bin/phpunit

  3. Composer auditNo advisories

    Audits the exact versions in composer.lock and fails the pipeline on a known advisory.

    composer audit --locked

  4. SBOMValidated

    A CycloneDX bill of materials, validated and kept as a job artifact. The app's composer.json is never touched.

    composer CycloneDX:make-sbom --output-format=JSON --validate

  5. PintClean

    The app's own Laravel Pint, in test mode, with the app's own pint.json.

    vendor/bin/pint --test --config=pint.json

  6. PHPStanNo errors

    The app's own PHPStan, writing its findings as a Code Quality report.

    vendor/bin/phpstan analyse --error-format=gitlab

  7. ESLint · PrettierClean

    The app's own ESLint and prettier --check, installed from the lock with scripts off.

    npx --no-install eslint .

  8. A11y · axe-coreNo violations

    axe-core in Playwright on the app's pages, light and dark, at 320 and 1280 px. WCAG 2.1 AA by default; one input adds 2.2 AA.

    node check.mjs config.json

  9. ClearanceCleared for takeoff

    Every gate green. The release is free to leave for Citadel.

Checklist complete. Tray tables up, tests green.

Type certificate

The inputs contract

Your include: lines lean on names: an input like php_versions, a job called php-test that your own file may extend. Every one of them is written down in contract/inputs.json, and Preflight's build fails the moment a template drifts from it.

  1. Renames are announced. An input or job is renamed or removed only in a release whose Upgrading notes list it under Breaking. Before 1.0 that is a new minor, never a patch.
  2. Tighter counts too. A pattern that stops a value you used to pass is breaking, and gets the same notice.
  3. Defaults move in the open. Image digests are defaults, and Renovate moves them. Leave an input unset and you get the new default when you move the pin.

Before you move a pin, read the diff:

$ git diff 0.3.1 0.4.0 -- contract/inputs.json

From the flight manual

Read before flight

The limits of a shared CI template, and how Preflight checks its own.

Warning

A component is not a lock. An app's own .gitlab-ci.yml is merged over the included jobs, so it can override a job's keys, skip it with rules, or delete the include: line. Preflight makes the safe pipeline the easy one; Rollcall is where skipped or weakened gates show up.

A preflight checklist only works if the pilot reads it.

Caution

Same instance only. Components work only inside the GitLab instance that hosts Preflight, so another instance needs a mirror. git.wayne.edu now has an instance runner, and the stack's CI runs on it. A git.wayne.edu instance runner is still strongly recommended, so that capacity stays there.

Note

Every image is pinned by digest (name:tag@sha256:…), so a repointed tag cannot quietly change what a pipeline runs. The php-test matrix is the one exception, tag-pinned on purpose so each job gets the newest PHP patch. Pins change only through a reviewed merge request.

$ docker buildx imagetools inspect <image>:<tag>

Preflight's own preflight

The checklist checks the checklist

composer ci lints every template and workflow for unsafe CI patterns before the fixture tests run.

  • privileged privileged: true
  • dind-service Docker-in-Docker services
  • docker-sock references to docker.sock
  • kaniko-image Kaniko images
  • unpinned-action GitHub uses: not pinned to a 40-character SHA
  • image-no-tag an image with no tag
  • image-latest an image on latest
  • image-no-digest a warning: tagged, but not pinned by digest

A known warning goes in lint-allow.yml, and every entry needs a reason, so someone has to write down why. On every pipeline, tests/ComponentsContractTest.php also holds each template to contract/inputs.json: every input's name, type, default and pattern, and every job's name.
